# iCloudカレンダー接続の小さな検証

BittyのiPhoneアプリを閉じた状態で、Mac（またはRunnerを置く環境）からiCloudの予定を
直接読めるか確認する、Python 3.10以降の標準ライブラリだけのプログラムです。
既存のアプリ・Runnerの実装には接続していません。再起動・アプリビルド・pip installは不要です。

## 実行

1. 対象の予定が「このiPhone内」やGoogle/Exchangeではなく、iCloudに保存されていることを確認します。
2. Apple Accountの2ファクタ認証を有効にし、[Apple公式手順](https://support.apple.com/en-us/102654)に従って
   `account.apple.com`で検証専用のアプリ用パスワードを発行します。
3. BittyのiPhoneアプリを閉じ、対話ターミナルで次を実行します。

```sh
python3 scripts/calendar/icloud_probe.py
```

Apple Accountとアプリ用パスワードを、実行後の入力欄へ入力します。
パスワードは非表示で入力し、ファイル・環境変数・コマンド引数へ保存しません。
チャットへ貼り付ける必要はありません。通常のApple Accountパスワードは使いません。

現在から7日間をUTCで検索し、カレンダー名と、読めた予定オブジェクト数を表示します。
検索日数は`--days 1`から`--days 31`で変更できます。
予定名・メモ・URLや認証情報は表示しません。カレンダー名は表示されます。

```text
{"calendar": "Work", "event_resources": 3}
読み取り成功: VEVENT対応カレンダー 1 件
```

成功すれば、この環境からiPhoneアプリを介さずiCloudへ認証し、カレンダー一覧と
指定期間の予定データを読めたことを確認できます。予定があるカレンダーで試すと確実です。
0件ならその期間の予定データ自体は未検証です。繰り返し予定も1オブジェクトとして数えるため、
iPhone上の予定の表示件数とは一致しない場合があります。

## 検証の範囲

- `PROPFIND`と`REPORT`だけを使う読み取り専用です。予定の作成・更新・削除は行いません。
- 接続先はHTTPSの`icloud.com`とそのサブドメインだけです。転送先も毎回検証します。
  通常のTLS証明書検証を使います。自己署名証明書の許可や証明書検証の無効化は行いません。
- 1通信30秒、応答8MiB、転送は3回までです。予定が多ければ検索日数を短くしてください。
- 件数は予定オブジェクト数です。繰り返し展開・予定の詳細表示・書き込み・常時稼働・
  本番向け認証情報保存・既存ツールの切り替えは、この検証には含めません。
- 検証後に不要になったアプリ用パスワードはApple Accountの設定から失効できます。

## オフラインテスト

```sh
python3 -m unittest discover -s scripts/calendar -p 'test_*.py' -v
python3 scripts/calendar/icloud_probe.py --help
```

テストは固定XML応答を使い、実アカウントやiCloudの予定にはアクセスしません。
