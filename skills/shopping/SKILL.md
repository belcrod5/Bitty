# 買い物

同梱の `scripts/amazon/` のコマンドを使い、Amazonの商品検索・詳細表示・購入履歴の表示を実行する。ブラウザ操作はAIで代行せず、Playwrightプログラムで行う。

## 実行

このSKILL.mdと同じディレクトリを `<skill>` とする。リンク経由で利用でき、原本は `/Volumes/SSD-500GB-SanDisk/work/bitty-public/skills/shopping/` にある。

実行ディレクトリを `<skill>/scripts/amazon/` に設定する。Node.js 22以降とGoogle Chromeが必要。依存パッケージがなければ同ディレクトリで `npm ci --cache .npm-cache --no-audit --no-fund` を実行する。

| 依頼 | コマンド |
| --- | --- |
| 商品検索 | `npm run search -- "検索語"` |
| 検索結果の指定番号の商品詳細 | `npm run detail -- "検索語" --index 1` |
| ASINを指定した商品詳細 | `npm run detail -- --asin B012345678` |
| 購入履歴（注文履歴）を開く | `npm run orders` |

検索語は依頼に合わせて渡す。指定がなければプログラムの既定値は「ボールペン」。`--index` は1始まりで広告も表示順に含む。ASINは実際の商品URLの `/dp/` に続く10桁の英数字を使う（上表のASINは書式例）。

画面を残してほしい依頼には `--keep-open` を追加する。この場合はブラウザを手動で閉じるまでプロセスが継続するため、結果ファイルに成功が記録された時点で完了を報告できる。通常は結果保存後にブラウザを閉じる。必要なら `--headless` で実行する。

## 各コマンドの動作

- 検索：ホームを開き、`#twotabsearchtextbox` をクリックしてフォーカスを確認。1文字ずつ入力し、`#nav-search-submit-button` をクリックする。
- 検索から商品詳細：検索後、指定番号の検索結果の `data-asin` に対応する商品リンクをクリックする。ASIN指定時だけは詳細URLに直接遷移する。`#productTitle:visible` とASINの一致を確認する。
- 購入履歴：ホームの `#nav-orders` をクリックし、見出し「注文履歴」の表示を確認する。履歴URLの直開きではない。

文字入力ごととクリック直前に0.5〜1秒のランダム待機を入れる。マウス移動はランダムな中継点2〜4個、3次ベジェ曲線、変動する速度と途中停止を使う。クリック直前に対象が座標上にあることを確認する。この動作はプログラム内に実装済み。

`orders` はこのスクリプトの `.browser-profile/` を使用する。検索・詳細は通常一時ブラウザを使い、`--profile` を付けたときだけ同じ専用プロファイルを使う。既存の普段使いChromeのプロファイルは読み込まない。ログインコマンドやログイン待機はない。Amazonが認証画面を出したらその旨を報告し、ログイン操作には進まない。

## 結果とエラー

`artifacts/<日時>/result.json` の `success`、URL、商品タイトルなどで完了を確認する。操作記録は同じ場所の `events.json`、画面はPNGに保存される。終了コード0が成功、1が通常のエラー、2が `LOGIN_REQUIRED`。

要素は固定セレクタで取得し、通常20秒、検索結果・商品タイトル・履歴見出しは30秒でタイムアウトする。要素が見つからない、クリック位置が隠れている、商品番号が範囲外、ASINが不一致の場合も停止する。通常の失敗は `error.png` と `error.html` を保存する。認証画面はHTML・画像・認証URLのクエリを保存しない。

失敗したら保存されたエラーを確認して報告する。取得に失敗した要素をAIのブラウザ操作で調査することはできるが、代わりにAIでクリックして成功扱いにしない。CAPTCHAを自動突破しない。

## 操作範囲と保守

購入・カート追加は行わない。プログラムは購入系URLを遮断し、必要なAmazonの閲覧先へのGET/HEADの画面遷移だけを許可している。この制限を外して依頼を実行しない。

このスキルは指定された「買い物」オーケストレーターの `.agents/skills/shopping` から原本へのリンクで配置する。共通の `~/.codex/skills/` にコピーしない。保守は原本側で行い、コードを変更した場合は `scripts/amazon/` で `npm run check` と `npm test` を実行する。実行結果・ブラウザプロファイル・node_modulesはGit管理しない。
