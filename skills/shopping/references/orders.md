# 購入履歴の検索と再開

履歴の検索・検索語変更による絞り込み・ページ送りは同梱プログラムを使う。商品の判断は返されたJSONでAIが行う。AIブラウザ操作は未知の画面構造の調査に使い、通常の履歴検索を代行させない。

```sh
npm run chrome -- orders
npm run chrome -- orders-search "電池"
npm run chrome -- orders-results --offset 10 --limit 10
npm run chrome -- orders-next
npm run chrome -- orders-search "単3"
```

`orders` は現在が履歴ページなら再読み込みしない。それ以外では現在のページの注文履歴リンクをクリックする。検索欄はフォーカス確認後、1文字ずつ0.5〜1秒待って入力する。入力前に全選択と空欄を確認し、拡張経由で効かないことのある全選択ショートカットには依存しない。検索ボタンと次ページリンクには既存のマウス処理を使う。検索語変更も `orders-search` で行う（前の語とのAND検索を望むなら「電池 単3」のように全文を指定）。期間のドロップダウン操作は未対応で、表示中のフォームが保持している期間を引き継ぐ。期間外も含めて調査したとは報告しない。

JSONの `query`・`filter`・`startIndex`・`page` が現在の検索条件。`products` はASIN、商品名、詳細URL、表示中の注文内の位置を返す。注文番号・住所・認証トークンは収集しない。`orderCount` は表示ページの注文カード数、`productCount` は表示ページの商品数で、全履歴の総件数ではない。同じASINでも別注文のものは別行になる。

`nextOffset` があれば `orders-results` で同じページの続きを読み、`hasNextPage: true` なら `orders-next`。最終ページではクリックせず `pageChanged: false` を返す。1コマンド1ページで、全履歴の自動巡回はしない。空結果は画面の0件表示を確認できた場合だけ `empty: true`。未知のDOMは `ORDERS_LAYOUT_UNKNOWN` などのエラーで止め、0件と推測しない。

商品を見つけたら通常の `detail --asin` → AIが同じタブで選択 → `detail-current` → ユーザーの追加依頼があれば `cart-add`。履歴の「再度購入」ボタンは押さない。

## 認証後の再開

終了コード2・`VERIFICATION_REQUIRED` / `LOGIN_REQUIRED` が返ったら、Amazonの認証をユーザーに依頼し、同じタブと接続を残す。Chromeの接続許可の要求やタブ切替・再接続はしない。

```sh
# 同じタブで手動認証が済んだ後
npm run chrome -- orders-resume
```

`.orders-progress.json` に直近の履歴操作、検索語、移動元と移動先の検索条件、状態を保存する。カートの操作記録とは独立しており、履歴の再開で追加・削除を再実行しない。結果の `progress.resumeCommand` に再開コマンドを返す。ファイルはGit対象外・所有者専用。

- 認証が残っていれば操作せず再び終了コード2。
- 認証後すでに目的の結果ページなら、検索・ページ送りを再実行せずJSONを読む。
- 元のページに戻っていれば、保存した未完了の検索・次ページ移動を1回だけ行う。
- クリック前の認証なら、保存した検索語で処理を開始する。
- 無関係な検索・ページへ移っていたら `ORDERS_RESUME_MISMATCH` で停止。`orders-results` で現在の内容を読み、進め方を判断する。

未完了の操作があれば、同じ `orders-search` / `orders-next` を繰り返す代わりに `orders-resume` を使う。`ORDERS_PENDING` はこの案内。単なる要素不在やタイムアウトも自動連打しない。保存前の古い操作については `NO_ORDERS_PROGRESS` となるため、認証後に `orders-results` で現在のページを確認してから検索する。

接続が実際に切断された場合は接続手順に従うが、再接続後のタブが保存条件と異なるときは勝手に検索し直さない。Amazonの人間確認の発生を防ぐ機能ではない。
