# 単品追加とカート確認

## 実行範囲

ユーザーが指定した商品を数量1でカートに追加する依頼に使う。商品検索だけの依頼では追加しない。注文確定・購入・商品削除・数量変更・認証の操作は行わない。実装改善や検証の依頼だけでは実際の追加を行わない。

すでに追加成功が報告・記録されている商品は追加し直さず、`cart` で内容を確認する。ユーザーから「追加済み」と報告された事実と、プログラムで確認した事実を区別して伝える。

## ブラウザの選択

既定では専用プロファイル `.browser-profile/` を使用する。普段使いChromeのログイン状態とは別であり、既存Chromeでの追加を確認する用途に黙って切り替えない。

既存のログイン済みChromeで追加済みの商品を確認する場合は、まず接続済みブラウザツールのChromeとカートタブも調べる。**表示中のカートは [extension.md](extension.md) の固定プログラムで読み取れる。CDPの有無だけで停止しない。** CLIで操作する場合は `npm run browser-status` を実行し、CDPのURLをユーザーに尋ねて開始を止めない。 このコマンドは起動中の同一ユーザーのChromeについて、起動引数・DevToolsActivePort・待受ポートからCDP候補を探し、応答とAmazonタブのタイトル・URLパスを読み取る。ブラウザやタブを起動・移動しない。任意のポート範囲をスキャンしない。

- `available`：`--cdp auto` で対象商品・カートに合う一意の既存タブを使う。複数なら一覧のタイトル・商品から対象を特定し、`--tab-url` を渡す。ユーザーへの確認が必要なら商品やタブ名で尋ね、CDPのURLを探す作業をユーザーへ戻さない。
- `inspection_unavailable`：プロセス情報等の読み取りが制限されている。サンドボックス制限なら通常のローカル実行権限で同じ読み取りコマンドを再実行する。権限拒否を「CDPが無効」と断定しない。
- `unavailable`：`code` と理由を確認する。`CDP_UNAVAILABLE` は起動中Chromeに共有できるポートがない状態で、接続先URLを尋ねても解決しない。`CDP_UNREACHABLE` は候補への応答を確認できない状態、`CHROME_NOT_RUNNING` はChrome自体が見つからない状態。CLIの接続状態を表す結果であり、拡張経路の利用可否とは区別する。

ユーザーから実際の接続先が指定されている場合は `--cdp <接続先>` も使える。診断で利用不可でも、対応済みの読み取りは拡張経路で進める。設定変更や再起動が必要と決めつけない。現在のChromeの設定を勝手に変更しない。旧商品の削除が依頼に含まれていても、このスキルには削除コマンドがないことを別に報告する。普段のプロファイルのコピー、Chromeの再起動、認証回避は行わない。拡張経路のカート読み取りで追加ボタンをクリックしない。接続時は既存タブを使い、終了時は接続を切断するだけでタブを閉じない。

```sh
# 追加せず、現在のカートまたは認証状態を確認
npm run browser-status
npm run cart -- --cdp auto

# 新しい「単品追加」の依頼。ASIN・ID・タブURLは実際の依頼に合わせる
npm run cart-add -- --asin B012345678 --operation request-001 \
  --cdp auto

# 過去の操作一覧を確認（ブラウザを開かない）
npm run cart-status

# 同じ依頼の保存状態を確認
npm run cart-status -- --operation request-001
```

追加の実行前に `npm run cart-status` で過去の記録を確認し、同じ依頼が追加済み・成否不明ならその操作を再利用する。

`--operation` は依頼ごとの識別子。実行前に決め、同じ依頼の再実行・再開では同じIDを使う。失敗を回避する目的でIDを作り直したり、`.operations/` の記録やロックを削除したりしない。新しいIDはユーザーが別の追加を明示した場合だけ使う。

## 状態の扱い

操作記録は `.operations/<ID>.json`。同一操作をロックし、追加クリックのマウスダウン前にディスクへ記録する。

| addition | 意味と次の動作 |
| --- | --- |
| `not_started` | 追加未送信。数量1・商品ASIN・POSTフォームを確認してから1回だけ送信する |
| `submitted` | 送信直前の記録。異常終了からの再開時は成否不明として扱い、再送しない |
| `unknown` | 成功を確認できない。再追加せず、読み取りだけで確認してユーザーに報告する |
| `confirmed` | 対象ASINを含む追加成功表示を確認済み。再開時はカート表示だけを行う |

CLIではカート内に対象ASINが見つかったかを `targetPresent` に保存する。拡張経路の読み取り関数は同じフィールドを戻り値に返し、操作記録を更新しない。見つからなくても追加済みの記録は取り消さず、自動で追加し直さない。

`cart` は `visible`（内容表示）、`verification_required`（人間確認）、`login_required`（ログイン要求）、`unknown`（表示結果不明）、`not_opened`（未遷移）を別に記録する。

**`addition: confirmed` かつ `cart: verification_required` は、追加済みでカート表示だけが未完了。全体を追加失敗と解釈して再実行しない。** `retryAdd: false` は成否不明でも再追加しないことを意味する。クリック後の応答喪失・プロセス停止では成功とも失敗とも断定しない。

フォームの数量が1以外・数量を取得できない・ASIN不一致・未対応フォームなら、追加せず停止する。数量を勝手に変更しない。追加用POSTは対象フォーム・ASIN・数量1に一致する1回だけ許可する。カート移動は成功画面の「カートに移動」リンク、またはヘッダーのカートリンクをクリックする。

## 認証と結果

`/checkpoint/continue`、`/ap/`、CAPTCHAのURL・画面を判定し、自動で解かず停止する。認証発生の原因はこの結果だけでは判断しない。マウス速度や待機時間の変更で認証を回避できると約束しない。

URLのクエリ・フラグメント・認証情報は、例外メッセージを含めて保存前に除去する。認証画面の画像・HTMLは保存しない。カート操作ではエラーHTMLも保存しない。

終了コードは0（必要な表示まで完了）、2（認証要求）、3（追加の成否不明）、1（その他のエラー）。後続の表示失敗でも、操作記録の `addition` を優先して追加済みか判断する。`artifacts/` の `result.json`、`.operations/` の記録を読み、追加結果とカート表示結果を分けて報告する。
