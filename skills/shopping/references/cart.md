# カートの追加・合計確認・色変更

## 実行範囲

ユーザーが指定した商品を数量1でカートに追加する依頼に使う。商品検索だけの依頼では追加しない。色変更の依頼では、新色を追加して確認後、指定した旧行だけを削除できる。注文確定・購入・一般の商品削除・数量変更・認証の操作は行わない。実装改善や検証の依頼だけでは実際の追加を行わない。

すでに追加成功が報告・記録されている商品は追加し直さず、`cart` で内容を確認する。ユーザーから「追加済み」と報告された事実と、プログラムで確認した事実を区別して伝える。

## ブラウザの選択

既存のログイン済みChromeを使う場合は [playwright-extension.md](playwright-extension.md) に従って保持接続を使う。追加済みの商品を見るだけなら、公式Playwright拡張の `cart` で確認できる。初回設定や切断後の再接続を除き、操作ごとに接続を作り直さない。接続先URLをユーザーに探させない。

新規単品追加も同じ公式拡張接続を使う。カート追加のために直接接続を作ったり、Chromeの接続許可を求めたりしない。公式拡張が未設定なら初回設定を行い、自動で別方式に切り替えない。ChatGPTブラウザツール方式は追加済み商品の表示確認に利用できる。

```sh
# ブラウザ操作の前に、同じ追加依頼の保存状態を確認
npm run cart-status -- --operation request-001

# 追加せず、既存Chromeでカートの内容・認証状態だけを確認
npm run chrome -- status
npm run chrome -- cart

# ユーザーが新規単品追加を依頼し、公式拡張がconnectedのときだけ実行
npm run chrome -- cart-add --asin B012345678 --operation request-001 --tab-url <実際のタブURL>

# 衣類：詳細JSONで確認した正確な表示値と価格上限を指定する
npm run chrome -- cart-add --asin <最終子ASIN> --operation <同じID> --color "０１ブラック" --size "L" --max-price 1648
```

専用ブラウザの利用を意図している場合だけ従来の `npm run cart` / `npm run cart-add -- ...` を使う。その `.browser-profile/` は普段使いChromeのログイン状態とは別なので、既存Chromeの確認から黙って切り替えない。普段のプロファイルのコピー、Chromeの再起動、認証回避は行わない。色変更に伴う単品削除だけが対応範囲。その他の旧商品の削除は未対応であることを別に報告する。接続の停止ではタブを閉じない。

追加の実行前に `npm run cart-status` で過去の記録を確認し、同じ依頼が追加済み・成否不明ならその操作を再利用する。

`--operation` は依頼ごとの識別子。実行前に決め、同じ依頼の再実行・再開では同じIDを使う。失敗を回避する目的でIDを作り直したり、`.operations/` の記録やロックを削除したりしない。新しいIDはユーザーが別の追加を明示した場合だけ使う。

## 合計金額

`cart` の `subtotalText`・`subtotalYen`・`subtotalLabel` はAmazonが表示する選択中商品の小計。`allItemsSubtotalYen` はカート内の全有効商品の単価×数量の合計で、未選択商品も含む。`allItemsQuantity` は商品種類数ではなく数量の合計。`items[].selected` で選択状態を確認できる。

価格または数量が欠けている場合、全商品の合計は `null`・`totalsComplete: false` とし推測しない。選択分の集計との一致は `subtotalMatchesSelectedItems`。不一致ならページ更新中や割引などを調べ、表示小計と計算額を区別する。送料・ポイント利用・クーポンなどを確定する購入画面は開かないので、最終支払額とは言わない。

## 追加済み商品の色変更

「今のフリースを赤に」などの依頼では、直前の操作記録とカートから置換元の具体的ASIN・数量1を確認する。元の追加記録を変更しない。新しい変更依頼IDを決め、同じ変更の再開ではそのIDを使う。

```sh
npm run chrome -- detail --asin <元の子ASIN>
# variationsから同サイズの希望色の子ASINを選び、実際の色・サイズ・価格を再確認
npm run chrome -- detail --asin <新しい子ASIN>
npm run cart-status -- --operation <変更依頼ID>
npm run chrome -- cart-replace --from-asin <元の子ASIN> --asin <新しい子ASIN> --operation <変更依頼ID> --color <実表示値> --size <同サイズの表示値> --max-price <確認した円価格>
```

`cart-replace` は既存Chrome接続専用。新色が既にカートにある・元の行が複数/数量1でない・同サイズの色違いと確認できない場合、追加前に停止する。新色を1回追加し、カート内の数量1・価格上限を確認してから、固定した元の行IDの「削除」を1回だけクリックする。他の行には操作しない。変更後の「今のフリース」は変更記録の新しい `asin` を参照し、履歴の `fromAsin` を追加し直さない。

結果は `addition` と `removal` を別に保存し、旧ASINが消えて新ASINが数量1で残れば `replacementConfirmed: true`。新色の追加成功・成否不明では再追加しない。削除の応答が不明なら、同じIDでGETのカート読み取りから再開する。旧行がなければ削除済みと確認する。同じ行ID・数量1が残っている場合だけ、その行の削除段階を再開できる。別の行IDなら削除しない。1回の実行内で送信後のクリックを繰り返さず、タイムアウト時は `REMOVAL_UNKNOWN` と両色が残っている可能性を報告する。新色を勝手に削除して元に戻すこともしない。認証が出ても途中状態を保持する。

## 状態の扱い

操作記録は `.operations/<ID>.json`。同一操作をロックし、追加クリックのマウスダウン前にディスクへ記録する。

| addition | 意味と次の動作 |
| --- | --- |
| `not_started` | 追加未送信。数量1・商品ASIN・POSTフォームを確認してから1回だけ送信する |
| `submitted` | 送信直前の記録。異常終了からの再開時は成否不明として扱い、再送しない |
| `unknown` | 成功を確認できない。再追加せず、読み取りだけで確認してユーザーに報告する |
| `confirmed` | 対象ASINを含む追加成功表示を確認済み。再開時はカート表示だけを行う |

`cart-add` の結果には対象ASINが見つかったかを `targetPresent` に保存する。`cart` では返された `items` と対象ASINを照合する。ChatGPTブラウザツール方式の関数は `targetPresent` を戻り値に返し、操作記録を更新しない。見つからなくても追加済みの記録は取り消さず、自動で追加し直さない。

`submitted`・`unknown` でも、同じブラウザに対象ASINを含む追加成功画面が残っていれば、再送せず表示の読み取りだけで成功確定へ進める。単にカート内に商品があることだけでは、その追加の成功証明とはしない。

`cart` は `visible`（内容表示）、`verification_required`（人間確認）、`login_required`（ログイン要求）、`unknown`（表示結果不明）、`not_opened`（未遷移）を別に記録する。

**`addition: confirmed` かつ `cart: verification_required` は、追加済みでカート表示だけが未完了。全体を追加失敗と解釈して再実行しない。** `retryAdd: false` は成否不明でも再追加しないことを意味する。クリック後の応答喪失・プロセス停止では成功とも失敗とも断定しない。

フォームの数量が1以外・数量を取得できない・ASIN不一致・未対応フォームなら、追加せず停止する。数量を勝手に変更しない。クリック直前にも送信フォーム全体を検査し、対象ASIN・数量1・通常追加のPOST先に一致するボタンを1回だけクリックする。ページの通信制限は補助で、公式拡張のService Worker経由通信まで遮断する保証はない。カート移動は成功画面の「カートに移動」リンク、またはヘッダーのカートリンクをクリックする。

色・サイズのある商品は、[catalog.md](catalog.md) の手順で最終子ASINを選び、`--color`・`--size` に実際の表示値を指定する。該当する寸法の指定がなければ追加しない。`--max-price` は表示商品価格の上限（整数の円、送料等は含まない）。選択状態が取得できない・不一致・価格超過なら送信前に停止する。マウス移動中に選択値や表示価格が変わった場合も停止する。

条件は操作記録に保存し、同じIDで書き換えない。未送信の記録に不足条件を補うことはできる。再開時は省略した条件も保存値を引き継ぐ。カートJSONの `variantText` と `priceText` は表示の読み取り値で、成功判定は最終子ASINの存在確認。色・サイズ・価格のカート表示もAIが照合して報告する。

## 認証と結果

`/checkpoint/continue`、`/ap/`、CAPTCHAのURL・画面を判定し、自動で解かず停止する。認証発生の原因はこの結果だけでは判断しない。マウス速度や待機時間の変更で認証を回避できると約束しない。

URLのクエリ・フラグメント・認証情報は、例外メッセージを含めて保存前に除去する。認証画面の画像・HTMLは保存しない。カート操作ではエラーHTMLも保存しない。

終了コードは0（必要な表示まで完了）、2（認証要求）、3（追加または削除の成否不明）、1（その他のエラー）。後続の表示失敗でも、操作記録の `addition` を優先して追加済みか判断する。`artifacts/` の `result.json`、`.operations/` の記録を読み、追加結果とカート表示結果を分けて報告する。

## 実地確認

2026-11-22、サブエージェントが検索・候補比較・サイズ表の取得・子ASIN選定から、ARONAフリース（B01N590ZE7、０１Ｂブラック・LL・1,648円）の数量1追加まで実行した。追加後の移動がクリック前の座標検査で停止した際も再追加せず、カート読み取りで確認した。表示中のヘッダーカートリンクを優先するよう修正し、新しい価格DOMにも対応した。読み取り再開で色・サイズ・価格・数量1を照合済み。操作IDは `fleece-trial-20261122-01`、`addition: confirmed`・`cart: visible`・`retryAdd: false`。同じ試験を再追加しない。購入は行っていない。

同日、続く色変更の実地試験で、黒LL（B01N590ZE7）から赤系の１２ＢワインLL（B01MXRX6T8）へ置き換えた。変更前後のカート小計と全有効商品の単価×数量の合計はいずれも20,017円、数量合計12。新色は数量1・1,648円、黒は除去済み、他の行のASIN・数量・単価・選択状態は一致した。操作IDは `fleece-red-20261122-01`、追加・削除とも `confirmed`、`replacementConfirmed: true`。今のフリースはワインのASINを参照し、この変更を再追加しない。削除済みの表示行（`data-removed=true`）は集計から除外する。
