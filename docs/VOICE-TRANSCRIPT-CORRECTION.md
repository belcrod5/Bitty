# Voice transcript correction

After STT returns a final transcript, the shared `useStreamingStt` hook asks the Runner for one contextual correction before its existing automatic send path. Recent visible conversation messages are bounded on both client and Runner and serialized as data. Typed messages and manual transcript submissions do not enter this path.

The Runner connects to the already running Codex app server and starts a new ephemeral thread for each correction. It uses the fixed `private_runner/logs/stt-correction-workspace` scratch directory; the logs directory is shared between worktrees. It sets `project_doc_max_bytes: 0` to prevent ancestor `AGENTS.md` files from entering the turn, disables configured MCP servers, apps, plugins, shell tools, hooks, memories, and agents, and requests a structured `{changed,text}` result. It checks the output and rejects any observed tool activity. The correction model and reasoning effort are persisted together in the existing STT settings file; the default is GPT-6 Luna with low effort. No live latency claim is made.

The isolation settings follow the [Codex app server documentation](https://learn.chatgpt.com/docs/app-server) and [config reference](https://learn.chatgpt.com/docs/config-file/config-reference).

An unchanged result sends immediately. A changed result appears in a plain card above the glowing voice input and sends at a single three-second deadline unless tapped to send sooner. The preview compares Unicode graphemes locally: inserted or replaced text gets a subtle cyan underline, while removed original text appears inline with a muted strikethrough. Long changed regions are grouped into one coarse highlighted span to bound comparison work. The send icon's circular progress ring reads the same deadline and motion settings; its visual updates cannot delay sending. The edit icon stops the timer and turns the same card into a text editor; its send icon submits only the latest edited text. The X icon discards the correction and restores the original STT transcript as a manual draft without restarting correction or automatic sending. Changing the conversation, stopping, leaving the app, or unmounting invalidates a pending correction and preserves an edited draft where appropriate. A correction error leaves the finalized transcript as an editable draft and shows an error; it never guesses or silently sends. The reply cycle starts only when the actual send begins.

Local tests use a mock app server and mock STT transport. Real model quality, account availability, and device timing still require user verification with the worktree Runner and iOS app.
