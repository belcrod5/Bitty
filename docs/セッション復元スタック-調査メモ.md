## 症状(ユーザー報告)

- **LLMストリーミング中のセッションのチャット画面を開くと「セッションを復元中...」表示のまま固まり、履歴が表示されない**

- 検証1〜3(一覧表示/新規スレッド作成+送信/バックグラウンド復帰)は正常

## 一次調査の結果(2026-08-02、worktreeサーバー a2de9e3 稼働時)と食い違い

- 当該時間帯のログで restore 失敗として見つかったのは、未送信のクライアント生成セッション `019fc157-…` の `session_restore_error "session not found"`(16:23:19、16:30:08 JST)のみ
- 一方、**ストリーミング先セッション(e9a371…)の restore は 16:20:23 / 16:32:22 に count=20 で成功記録**があり、ユーザー報告と一致する失敗ログは未発見
- → ログ上の候補とユーザー報告が一致していない。**症状の再現とログ突き合わせからやり直す必要がある**
- 仮説候補: restore 自体はサーバー側で done になっているのに、クライアントのオーバーレイ状態が解除されない(UI状態管理側の問題)可能性も疑うこと
