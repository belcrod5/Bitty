# オーケストレーションチャットの分離

各チャットを独立した専門家として育てるため、`orchestratorId` を知識・保存領域・実行環境の所有単位にする。
モデル本体の事前知識を削除する機能ではない。Bitty が追加する知識と、実行時に参照できる情報を分離する。

## 所有範囲

| 項目 | 境界 |
| --- | --- |
| 会話履歴、設定、親セッション | チャット固有の context store |
| 長期メモリ、要約、最近の会話 | 固有 workspace の `voice-memory/` |
| 学習候補、採用した好み・手順・スキル | 固有 workspace の `orchestrator-learning/` |
| 学習設定、評価・修正履歴、提案、利用記録 | 同じ固有 learning store |
| 学習の使用量、予算判定、価格設定 | 固有 learning store の `usage/` |
| To Do、完了した To Do、その他の成果物 | 固有 workspace |
| Codex 設定、セッション、ネイティブ子エージェント | 固有 App Server プロセスと `CODEX_HOME` |
| HOME、XDG 設定、一時ディレクトリ | 固有 runtime home |

メインチャットにも例外を設けない。メインの workspace は context root の `workspace/`、追加したチャットの workspace は `orchestrators/<id>/workspace/` に置く。ランタイム用の `runtime-home/` は workspace の外に置き、モデルから読めないようにする。

チャット一覧・選択状態・認証・通知・スケジュールの実行基盤は Runner が管理する。これらの管理情報を他チャットのモデルの知識として注入しない。認証は実行基盤で共有するが、トークンを各 workspace にコピーしない。

## 実行時の制限

独立した Codex App Server を起動し、モデルには自分の workspace だけを許可する。通常の会話と、要約・話題判定・学習・To Do 表示の生成に同じ所有境界を使う。

グローバルのメモリ、設定、AGENTS 指示、スキル、プラグイン、MCP 接続を継承しない。採用したスキルは自分の learning store から版とハッシュを指定して読む。スキルの全チャット共有操作は受け付けない。

外部ネットワーク、Web 検索、外部アプリ、カレンダーは既定で利用できない。汎用の Bitty Runner セッションを起動・再開する `voice_subagent` ツールも公開しない。そのバックエンドは通常の共有環境を使うため、作業ディレクトリだけの指定では分離にならない。Codex のネイティブ子エージェントは同じ専用ランタイムと権限境界に属する。

外部プロジェクトや接続サービスを専門家に追加するには、今後、そのチャットに対する明示的な許可の契約が必要になる。既存の Runner 全体への workspace 許可を、各専門家への情報共有許可とは扱わない。

必要な権限境界を実行環境が確認できない場合は、共有環境へ戻さず実行を失敗させる。

## 既存データの一度だけの準備

既存の共有データはすべてメインへ引き継ぐ。追加の専門家は空のメモリ・学習・workspace から始める。
ランタイムには移行処理を組み込まない。未準備の旧保存形式を開いた場合は、明確なエラーで停止する。

準備は `private_runner/scripts/prepare-orchestrator-isolation.mjs` を明示的に一度だけ実行する。
モデルによる分類はせず、共有 workspace 全体（長期メモリ、学習・採用済みスキル、評価・修正・提案・利用記録、使用量台帳、設定、To Do・完了アーカイブ、その他のファイル）をメイン専用 workspace へコピーする。
旧学習の所有者はすべて `main` に変更し、元の所有者を `sourceOrchestratorId` に残す。根拠の会話 ID・番号・操作 ID は保持する。
旧 pending の根拠も保持するが、古いモデル実行の batch は破棄し、次回は新しく分析する。元の batch はバックアップに残る。

会話履歴とチャット設定は各チャットに残す。旧親セッションは再開しない。
旧会話は履歴画面に表示するが、新しいモデルの会話文脈・話題判定・学習へ自動的に再投入しない。
これにより、メイン以外の専門家へ共有知識を再導入せず、忘却したデータの再学習も防ぐ。
メインは元の共有メモリの ID と会話番号を引き継ぎ、以後はメインの会話だけを蓄積する。

### 操作手順

旧 Runner 側で実行中・結果不明の処理を終了または明示的に中断してから、Runner と Codex App Server を停止する。
データを共有する別 worktree の Runner も起動しない。
次のコマンドは対象 worktree のルートで実行する。`CONTEXT_ROOT` は既存データの保存先に置き換える。

```sh
./private_runner/run-local.sh stop --mode full
set -a
source private_runner/.env
set +a
CONTEXT_ROOT=/absolute/path/to/main/private_runner/logs/voice_context/v1
node private_runner/scripts/prepare-orchestrator-isolation.mjs \
  --root "$CONTEXT_ROOT" \
  --runner-port "${RUNNER_PORT:-${PORT:-8788}}" \
  --codex-port 4500
```

`--codex-port` は実際の `CODEX_APP_SERVER_LISTEN` のポートを明示する（上記の `4500` は例）。
最初は検査のみで、データを書き換えない。件数を確認した後、同じコマンドの末尾に `--apply` を付けて実行する。
起動中のポート、未完了処理、リンク、既存の専用 workspace、同期できていない旧メモリ・学習を検出した場合は停止し、上書きしない。

適用時は一時ディレクトリでコピー・所有者変更・通常の保存形式の検証を済ませ、旧 context root を `v1.before-isolation-<UUID>` に退避してから切り替える。
元の共有 workspace もそのまま残す。バックアップには全会話履歴・旧設定・実行状態が残る。
以前の起動時移行を既に試した保存先は、専用メモリが空で、学習が元のコピーのままかを検査する。
新しい知識・評価・修正・利用記録・有料実行や設定変更があれば、自動統合せず停止する。
空のままと確認できた場合だけ、元の共有データをメインへ引き継ぎ直す。
その際も以前の各専用 workspace 全体をメインの `previous-isolation/<orchestratorId>/` に保存し、独自ファイルや To Do の別版を失わない。
ランタイム用の HOME は workspace の外のまま保持し、モデルが読めるアーカイブへはコピーしない。
完了済みの保存先へ再実行しても、元データを再取り込みしない。
準備が完了した後に通常の再起動を行う。サーバー起動や再起動からこのスクリプトを自動実行しない。

## クリアと削除

メモリのクリア、会話のクリア、学習項目の忘却、チャットの削除は、指定された所有者だけに適用する。別チャットが実行中でも、対象チャットの独立した操作を妨げない。チャット削除時は専用ランタイムを停止してから、そのチャットの保存領域を削除する。

クライアントは全学習リクエストに `orchestratorId` を付け、応答の所有者も確認する。チャットを切り替えた後に遅れて届いた応答で別チャットの表示を上書きしない。メモリクリアは、Runner が `isolationVersion: 1` を返したチャットだけで有効にする。
