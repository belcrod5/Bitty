# オーケストレーションチャットの分離

各チャットを独立した専門家として育てるため、`orchestratorId` を知識・保存領域・実行環境の所有単位にする。
モデル本体の事前知識を削除する機能ではない。Bitty が追加する知識と、実行時に参照できる情報を分離する。

## 所有範囲

| 項目 | 境界 |
| --- | --- |
| 会話履歴、設定、親セッション | チャット固有の context store |
| 長期メモリ、要約、最近の会話 | 固有 workspace の `voice-memory/` |
| 学習候補、採用した好み・手順・スキル | 固有 workspace の `orchestrator-learning/` |
| 学習設定、評価・修正履歴、提案、利用記録 | 同じ固有 learning store |
| 学習の使用量、予算判定、価格設定 | 固有 learning store の `usage/` |
| To Do、完了した To Do、その他の成果物 | 固有 workspace |
| Codex 設定、セッション、ネイティブ子エージェント | 固有 App Server プロセスと `CODEX_HOME` |
| HOME、XDG 設定、一時ディレクトリ | 固有 runtime home |

メインチャットにも例外を設けない。メインの workspace は context root の `workspace/`、追加したチャットの workspace は `orchestrators/<id>/workspace/` に置く。ランタイム用の `runtime-home/` は workspace の外に置き、モデルから読めないようにする。

チャット一覧・選択状態・認証・通知・スケジュールの実行基盤は Runner が管理する。これらの管理情報を他チャットのモデルの知識として注入しない。認証は実行基盤で共有するが、トークンを各 workspace にコピーしない。

## 実行時の制限

独立した Codex App Server を起動し、モデルには自分の workspace だけを許可する。通常の会話と、要約・話題判定・学習・To Do 表示の生成に同じ所有境界を使う。

グローバルのメモリ、設定、AGENTS 指示、スキル、プラグイン、MCP 接続を継承しない。採用したスキルは自分の learning store から版とハッシュを指定して読む。スキルの全チャット共有操作は受け付けない。

外部ネットワーク、Web 検索、外部アプリ、カレンダーは既定で利用できない。汎用の Bitty Runner セッションを起動・再開する `voice_subagent` ツールも公開しない。そのバックエンドは通常の共有環境を使うため、作業ディレクトリだけの指定では分離にならない。Codex のネイティブ子エージェントは同じ専用ランタイムと権限境界に属する。

外部プロジェクトや接続サービスを専門家に追加するには、今後、そのチャットに対する明示的な許可の契約が必要になる。既存の Runner 全体への workspace 許可を、各専門家への情報共有許可とは扱わない。

必要な権限境界を実行環境が確認できない場合は、共有環境へ戻さず実行を失敗させる。

## 旧共有データからの移行

旧共有 workspace と、その中のメモリ・学習・任意の成果物は削除しない。自動的に全チャットへコピーすることもない。

- 既存の会話履歴とチャット設定は保持する。旧親セッションは再開しない。
- 旧会話は履歴画面に残すが、新しいモデルの会話文脈・話題判定・学習履歴へ再注入しない。以前の回答には共有メモリ由来の情報が含まれる可能性があるため。
- 長期メモリは空から始める。移行時の完了済み会話番号を保存し、それ以前の会話から削除済みの記憶を再構築しない。
- 学習項目は `scope.orchestratorId` と全根拠の所有者が一致するものだけ引き継ぐ。置換対象が他チャットに属する項目は引き継がない。旧 `shared` フラグは持ち越さない。
- 公開済みの自分のスキルは、通常ファイル・サイズ・保存済みハッシュを確認してコピーする。改変やシンボリックリンクを見つけた場合は学習の移行を止め、他のチャットを巻き込まない。
- 旧学習の設定は値としてコピーし、その後はチャットごとに変更できる。
- 所有者名で特定できる自分の To Do と完了アーカイブを引き継ぐ。他チャットのファイルはコピーしない。
- 混在した旧 pending batch、評価・修正履歴、提案、利用記録、使用量台帳は旧保存先に残し、新しい保存先には取り込まない。

移行した learning store には件数と旧データ保管の情報を記録する。一度移行した保存先に、旧データを再インポートしない。移行後に忘却した項目も再起動で復活しない。

旧処理が実行中・結果不明の場合は、状態確認と明示的な中断だけを受け付け、新しいモデル処理は開始しない。旧セッションへの読み取りと中断は、保存済みの既知 ID だけで行う。旧処理が終端状態になった後に分離を完了する。結果不明を勝手に成功扱いしたり、実行を再送したりしない。

## クリアと削除

メモリのクリア、会話のクリア、学習項目の忘却、チャットの削除は、指定された所有者だけに適用する。別チャットが実行中でも、対象チャットの独立した操作を妨げない。チャット削除時は専用ランタイムを停止してから、そのチャットの保存領域を削除する。

クライアントは全学習リクエストに `orchestratorId` を付け、応答の所有者も確認する。チャットを切り替えた後に遅れて届いた応答で別チャットの表示を上書きしない。メモリクリアは、Runner が `isolationVersion: 1` を返したチャットだけで有効にする。
