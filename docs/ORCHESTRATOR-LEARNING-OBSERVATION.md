# オーケストレーターの継続学習・専用スキル・利用量ログ

継続学習設計の段階1〜3。設定画面の「学習・評価」で、全オーケストレーター共通のモデルとエフォートを選ぶ。初期値は未設定で、会話の差分記録だけを行う。モデルを保存すると有料の分析が起動し得る。「停止」はモデル設定を空にし、次の分析・再試行を止める。実行中の分析の利用量は引き続き記録する。

候補は「候補・未使用」、採用した方針は「採用済み」と表示する。通常候補の「回答に使う」で採用し、条件に合う回答へ渡す。停止案は「使用停止を採用」、置き換え案は「変更を採用」と区別する。「まとめて操作」を開いたときだけチェックを表示し、チェック自体は対象選びで使用状態を変えない。採用・見送りは候補50件まで、修正案の依頼は同じチャットの学習5件まで。修正案は次回の分析で候補を作成し、採用するまで回答には反映しない。根拠・更新日・管理操作は「詳細・管理」にまとめる。チャット限定が既定で、「全チャットで使う」の確認後に共有する。「専用スキルとして保存」はオーケストレータ専用領域への保存で、インターネット公開ではない。現在の依頼、手動のチャット設定、既存の承認規則が優先される。モデル未設定は新規分析を止める操作であり、採用済み項目の無効化ではない。適用停止は「使用を停止」、内容の削除は確認付きの「学習を削除」を使う。「この方針に戻す」は置き換え先を停止する可能性を確認してから復元する。既存の応答用モデル設定と共通Codexスキルには影響しない。初回開始以前の会話はインポートしない。再起動時には保持されている完了イベントから観測漏れを回収し、失われた範囲は欠損として表示する。

## 保存先と起動条件

共有workspaceの `orchestrator-learning/state.json` に未処理差分・候補・出典・欠損を、`orchestrator-learning/usage/ledger.json` に本文を含まない分析呼出の台帳を保存する。手動編集は行わない。既存Runnerの単一プロセスで所有する。

未処理8組または最古の差分から10分、最短5分間隔、同時1分析。会話の応答中は開始を待つ。1分析は16組・入力24,000 UTF-8 bytes以内。大きすぎる1組は欠損理由を残して除外する。失敗は元入力を保持して最大3回まで試す。日次予算に達すると分析を翌UTC日へ延期し、その間も観測は容量上限まで継続する。

呼出数はUTC日ごとに12回まで。入力・指示のbytesを用いた入力見積りと出力4,000 tokensを予約し、取得できたusageで精算する。入力見積りにはランタイム共通プロンプト等の未測定分があり、出力上限の強制も未確認のため、100,000 tokensは厳密な消費上限を保証しない。取得不能なusageは予約分を消費扱いにし、実測値と区別する。

## 利用量と単価の操作

以下は認証済みRunner接続の `channel: "agent"` のWebSocket操作。応答は同じ `requestId`、`<op>.result` の `payload` で返る。単価は以下の操作で設定する。専用の単価編集画面は設けていない。

| op | payload | 用途 |
| --- | --- | --- |
| `voice.learning.status` | `{}` | 設定、状態、候補、欠損、当日予算と利用量集計。unreadCountは未確認の候補数 |
| `voice.learning.read` | `{"items":[{"id":"<id>","version":1}]}` | 一覧で確認した候補の版だけを既読化。採用やモデル実行はしない。同時追加・更新された候補は既読にしない |
| `voice.learning.configure` | `{"model":"<modelId>","effort":"<対応effort>","settingsRevision":1}` | 既存モデル一覧から選択。revisionは直前のstatusを使う |
| `voice.learning.configure` | `{"model":"","effort":"","settingsRevision":2}` | 新しい分析・再試行を停止 |
| `voice.learning.decide` | `{"items":[{"id":"<id>","version":1}],"action":"adopt","reason":""}` | 候補を一括採用。actionはadopt/reject/retire/share/publish/restore |
| `voice.learning.retry` | `{"batchId":"<exhausted batch id>","settingsRevision":2}` | 保留した元入力を現在設定で1回だけ再試行。累積試行回数・間隔・日次予算を維持 |
| `voice.learning.change` | `{"items":[{"id":"<id>","version":2}],"instruction":"手順を統合して条件を保持"}` | 同じ分析バッチで編集・統合・廃止案を依頼。自動採用しない |
| `voice.learning.correct` | `{"evaluationId":"<id>","version":1,"score":65,"reason":""}` | AI評価を保持したままユーザー訂正を追加。score=nullは理由必須。同一の最新訂正は追加しない |
| `voice.learning.correction.cancel` | `{"evaluationId":"<id>","version":1,"correctionIds":["<id>"]}` | 未反映訂正、または空入力でresolution.itemId=nullが明示された反映済み訂正をまとめて取消。履歴は保持 |
| `voice.learning.forget` | `{"items":[{"id":"<id>","version":2}]}` または `{"all":true}` | 項目と関連する前身・後継、保存版、評価、履歴を忘却。全学習の忘却はUIで確認する |
| `voice.learning.delivery` | `{"orchestratorId":"main","operationId":"<UUID>"}` | 実際の配送・今回の専用読取・親に残る読取。記録なしはnull |
| `voice.learning.proposal` | `{"id":"<proposalId>","decision":"declined"}` | 提案の採否を記録。acceptedも操作実行の許可にはならない |
| `voice.learning.usage` | `{"since":"2026-10-20T00:00:00Z","until":"2026-10-21T00:00:00Z","limit":100}` | 呼出明細とUTC日次集計。日時は開始時刻の範囲、limitは1〜10,000 |
| `voice.learning.price.configure` | `{"snapshot":{...}}` | 以後の予約に使う単価snapshotを設定 |
| `voice.learning.price.configure` | `{"snapshot":null}` | 以後の料金算定を未設定に戻す |

単価snapshotの形（単価は各契約の根拠を確認して設定する。以下のnullは未設定）：

```json
{
  "version": "<単価表version>",
  "source": "<単価の出典>",
  "currency": "USD",
  "validFrom": "2026-10-20T00:00:00Z",
  "contract": "<適用契約>",
  "model": "<実行モデルID>",
  "ratesPerMillion": {
    "input": null,
    "cachedInput": null,
    "output": null,
    "reasoningOutput": null
  }
}
```

金額は百万tokensあたりの非負数で設定する。呼出予約時点のsnapshotを保存するため、後の単価変更で過去の算定を上書きしない。料金は実請求額ではなく単価に基づく推定額。実際のモデル、usage内訳の包含関係、適用時点や単価が確認できない呼出は算定不能とし、ゼロ円とみなさない。cache/reasoningの内数を二重加算せず、異なる通貨は別集計にする。

要求model/effortと実際に報告された値は別欄に保持する。thread/startの既定effortは当該turnの実effortと断定せず、実報告がない値は不明のままにする。再試行・失敗もそれぞれ別callIdで記録する。再起動時に未精算の呼出は結果不明とし、予約量を維持する。

明細は最大90日・10,000件・20 MiB、UTC日次集計は最大400日・4 MiBで保持する。明細が整理された期間は集計と保持境界で判断する。台帳のcorruptionや容量超過は分析だけを停止し、既存の会話・記憶要約を継続する。

## 方針の反映・専用スキル・評価

有効項目の変更と取得内容のdigest変更だけを、既存の安全な親切替へ接続する。取消・忘却・対象外への変更では、子作業が残る旧親で次の応答を始めない。通常の直近10組（20メッセージ）は切替後も引き継ぎ、話題判定にも渡す。学習のrevision更新だけでは会話を除外しない。停止・置換・忘却した学習の根拠と配送・継承参照を持つ応答は、既存の永続的な除外記録に基づいて直近10組から除く。古い会話での穴埋めはしない。履歴原本は保持し、既存topicsも自動再注入する経路は追加していない。候補の却下、修正案依頼、評価訂正だけでは応答のrevisionを変更しない。

会話履歴には、実際に新しい親へ送信された発話の直前に「セッション切り替え」の区切りを表示する。ネイティブターンの開始記録（開始応答を失った場合は復旧した結果の記録）に境界を保存し、実行中の通知・状態照会・履歴で同じ情報を使う。失敗・中断しても境界は残る。初回の親作成や切替の予定だけでは表示しない。旧履歴は前後のネイティブ親IDが判明して異なる場合だけ表示し、理由は推測しない。

取得はチャット範囲、短い発動語、確認済み対象、件数と容量で選別し、意味上の適用は通常応答モデルが現在の依頼と照合する。追加の判定LLMや検索基盤は作らない。具体的な対象条件がある項目は、モデルが`orchestrator_learning.read_context({targets:[...]})`を呼ぶ。Runnerが当該ターンの成功したツールの実出力から対象名を照合して内部出典IDを導出する。ユーザー入力中のパスだけを確認済みとはしない。成功ツール出力の確認用保持は最大100件・各8,000 bytes。未確認、失敗、他ターン、学習ツール自身の出力は対象確認の根拠にならない。取得後の内容も親の適用項目として記録し、次ターンで対象を確認できなければ安全に切り替える。

スキル案は目的・発動条件・入力・手順・出力・例外・必要な承認を持つ。裏側AIは通常分析で作成・編集・統合・廃止案を返し、ユーザーが差分と範囲を確認して採用する。公開は別操作で、管理対象のみ`orchestrator-learning/skills/<id>/<version>.md`へ生成する。現行版と直前版だけを保持し、合計4 MiBを超える公開を保留する。管理2版のhashが手動変更されていれば上書き・自動整理を止める。廃止からの復元は後継を退役させ、忘却済み根拠は復活させない。自動公開は実利用の評価ゲートを満たすまで無効。

通常回答は配送された正確なid/version/hashを使い`orchestrator_learning.read_skill`で読む。各回答はアイコンと重複を除く知識・スキル件数を表示し、展開すると背景色・枠で区別したカードに、モデルに渡した学習、今回成功した読取、継続する親に残る参照を表示する。履歴を表示した時に既存の参照記録を1回取得し、開閉では再取得しない。LLM呼出しや定期取得は追加しない。LLMの自己申告を参照記録にせず、記録失敗・保持外・忘却後は未確認、読取記録が不完全な場合は既知件数に「+」を付ける。配送・読取が回答へ影響したことまでは保証しない。

AIの暫定評価は0〜100点、根拠不足はnull。元評価を保持し、ユーザー訂正は別レコードで保存する。点数を指定する場合は理由を省略できる。点数なしは空でない理由が必要で、両方空の訂正は拒否する。最新の有効訂正と同一なら追加せず、AI評価と同点・理由なしも初回は追加しない。UIは「評価を変更」で編集を開き、「保存」で確定する。根拠・期間・訂正履歴は折りたたむ。未反映訂正は個別または同一評価で一括取消でき、cancelledAtを残す。旧形式の空訂正は反映済みでもresolution.itemIdが明示的にnullなら取消でき、元のresolutionを保持する。最新の取消後は以前の有効訂正、なければAI評価を編集初期値に使う。取消済みと旧形式の空訂正は分析へ送らず、保存済みバッチに含まれていれば破棄して再構成する。進行中バッチが取消対象を参照した場合は中断・epoch失効するが、元pairと利用量は保持する。有意味な反映済み訂正と学習成果に紐付いた訂正は取消せず、新しい訂正で変更する。未反映の有効訂正と修正依頼を同じ分析へ優先入力し、新pairがなくても予算・間隔内で処理する。点数だけで指示や権限を作らない。

一括提案は、成功した当該ターンのツール出力で確認できた対象、件数、操作、除外、順序、失敗時の扱いを登録してから提案する。同じ対象hashの再提案を抑える。自然文の採否・結果確認も、同じ差分分析でproposal id/version/targetHashとユーザーの根拠pair・短い実引用に結び付ける。無反応とアシスタントの成功申告は結果確認にしない。提案採用は実行権限を作らず、実行・進捗・再開は既存の承認とチェックリストを使う。

忘却は会話原本・既存メモリーの消去と別の操作。利用量台帳は本文を持たず保持する。ファイル削除途中で失敗しても、本文を持たないcleanup対象IDを永続化して再試行し、完了したように表示しない。履歴は各100件・90日、利用記録は500件・30日、state全体4 MiBで保持する。有効な未反映訂正は期限で捨てず、取消済み・旧空訂正は通常の90日保持で整理する。

## 確認範囲

自動テストでは偽モデルと一時ディレクトリを使い、出典・復旧・予算・使用量精算・料金計算・設定画面を確認する。実データでの長期品質・料金実測、実機UIは別途確認する。ランタイムの取得項目はCodex app-server 0.163.0のschemaを確認した範囲で、未取得は推測で埋めない。

2026-10-21の少数実API検証は、既存Runnerと実会話を使わない隔離環境・合成8pairで実施した。GPT-6.1-Sol（分析medium、応答low）で分析、明示採用・公開、専用読取と成功記録、条件に合う短い報告、全忘却後の新しい親・配送0・旧recent非注入を確認した。最初の不正出力を契機に学習限定のJSON outputSchemaを上流で強制し、再分析を含め5ターン、計79,645 tokensで検証を停止した（cached/reasoningの内数を再加算しない）。単価未設定のため料金は算定不能。実利用での長期改善、実機UI、全種類の作業での適合は未検証である。

## 学習ダッシュボードの見方

画面は「会話のふりかえり」「学んだこと」「AI利用量」の順に表示し、モデル設定と診断は折りたたむ。学習状態は現在の状態だけを表示し、過去の状態を推測したグラフは作らない。

ふりかえりは保存中の評価（最大100件・90日）を評価日時のローカル日／月曜始まりの週でまとめ、AIの見立てと最新の有効なユーザー評価の平均・件数を分けて表示する。未採点は0点にせず、最新訂正が理由のみならユーザー点数は未評価。棒または一覧リンクをタップすると前面の専用画面で5件ずつ確認・訂正できる。固定ヘッダーから閉じると同じグラフへ戻り、背景のスクロール位置と期間を維持する。

ユーザーが採点しなくても通常の会話分析は進む。自動算出した点数は通常の次回分析へ戻さず、ユーザー訂正がある場合に元評価と訂正を次回分析のフィードバックへ渡す。

「学んだこと」は応答の好み・作業手順・一括作業の方針・保存済み専用スキルの件数を区別する。スキル案は保存前であることを表示する。「関連する回答で使う」スイッチは通常候補の採用／使用停止／停止中の再開を既存の判定APIへ送る。オンは条件に合う今後の回答で参照可能という意味で、即座に実行したことではない。置換・停止案の採用はスイッチにせず明示的な適用操作とし、再開は後継停止の確認を残す。一括操作のチェックは使用状態とは別で、ページをまたいで選択できる。

利用量は既存のusage読取APIだけで取得し、UTC日次集計を日／週で表示する。個別明細を集計へ再加算せず、予算の予約量を取得済みトークンに混ぜない。欠測・保持期間外・匿名化後の詳細は不明のまま表示し、推定料金は通貨別・未算定分と区別する。棒から前面の利用明細画面を開き、5件ずつ確認できる。開閉だけでは再取得しない。失敗・中断・処理中・結果未確認を完了と表示しない。

「学習の履歴」は何をしたかを日本語の動詞と人が読める日時で示し、理由・変更前後は詳細に畳む。UIの開閉・期間切替はモデル呼出しを追加しない。

### 学んだことの新着表示

メインのアイコン右下に、全オーケストレータの未確認候補の件数を表示する。会話の未読件数（右上）とは別に扱う。既存の一覧・未読通知に `learningUnreadCount` を加え、候補が保存された時に更新する。ポーリングや追加のモデル呼び出しは行わない。

「学習・評価」の読み込みに成功すると、取得した候補のid/versionだけを既読にする。有効化は別の操作で、既読にしても候補は採用されない。既読の版は候補の `readVersion` に保存し、再接続・別端末・再起動でも維持する。旧データの候補は未読扱い。旧Runnerに新着情報がなければ、バッジも既読操作も行わない。
