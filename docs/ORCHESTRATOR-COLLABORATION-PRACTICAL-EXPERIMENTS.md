# オーケストレーター逐次会話の実践3ケース

実施日: 2026-10-28。GPT-6 Luna / lowで架空の3ケースを各1回実行した。新規呼出しは24回（9＋6＋9）、形式検査を通過した結果23件と検査で停止した結果1件である。再実行・指示の調整後の再試験はしていない。

本人ごとに異なる架空背景が発言を通じて共有され、条件訂正にA/B/Cが追随する様子は観察できた。一方、終了理由はケースごとに異なり、すべて自然に閉じたわけではない。既存本人の知識結合や製品機能の検証ではない。

## 条件と初回からの変更

- 各ケースは合成A/B/Cの新規ephemeral threadを3本、同一接続で維持。A→B→C→Aの固定順、最大9手番、各45秒、発言120字以内、JSONのspeak/passという契約を使用した。
- カタログとthread開始応答で `gpt-6-luna` / `low` を確認し、fallbackを禁止。ツール無効configとMCP disabled確認、予期せぬtool検出時の中断ガードを維持した。全権限境界を実証した意味ではない。
- 今回は `--case` で問いと人格を切り替え、各本人だけに架空の背景をdeveloper指示で渡した。背景の全文を共有入力へ自動コピーせず、本人が発言した情報だけが他者へ届く。
- 共通指示へ「未実施の操作を実施済みと報告しない」を追加し、指示内の架空背景を利用してよいと明示した。初回との結果差をこの指示の因果効果とは評価しない。
- 新規意見がなければpass、合意反復を避け、残り手番を渡し、残り3以下は結論・未決に絞る指示を維持。同じ本文版の全員passで終了し、新しい発言・ユーザー補足でpass記録をresetした。
- 条件訂正ケースだけ3手番目の正常完了後にuser補足を挿入。予定補足前の全員passでは終了しない。生成中にユーザーが割り込む競合試験ではない。

問い・本人別背景・developer指示・差分入力・usageは以下のraw JSONに保存している。実行後に内容を補正していない。

## 課題と未確認範囲

releaseのB2・A4、incidentのA1は、それぞれ120字で語尾が文途中になっている。掲載は保存本文どおりで、scriptや手作業でsliceしていない。120字の指示・schema上限がある条件下の弱点として記録するが、生成・制約適用等のどの段階が具体原因かは断定しない。

形式検査で止まった事実と、議論内容の良し悪しは別である。全員passも、内容の正確性・十分な検討・ユーザー承認を意味しない。最新提案・未決・ユーザー判断が分かる終了表示は今後の課題であり、Aだけの総括runを必須にする旧案へ戻すものではない。

同じモデル・短い架空ケースを各1回のみ観察した。指示なし比較や再試行はなく、背景共有・終了指示の一般的な有効性は示していない。既存本人・本番・長期メモリ接続、toolOutput入力、ユーザー入力の競合、停止、障害復旧、永続化・再接続は未検証である。
